# 答題往返與結果解讀

狀態：整體共識已確認；正式規格已發布為 GitHub Issue #12，尚未實作。

## 已確認決策

1. 普通、挑戰與多人 PK 三種模式接入共用答題往返流程，負責送出、防重複、等待／請求逾時、結果驗證、錯誤分類與過期回應隔離。對外提供可採用判定或明確失敗／失效結果，伺服器保有答案正誤判定責任。
2. 各模式保留計分、倒數、連勝、揭曉、換題、對戰進度及結算責任；本輪不重做計分公式或排行榜／房間分數儲存方式。同次有效判定在目前題目或回合中最多採用一次；判定成功後的分數儲存失敗，不得因此重送判題或重複加分。

3. 三種模式均在目前題目的有效判定已被採用後記為已作答，答對或答錯皆算；網路失敗、請求逾時、無效回應及被捨棄的舊回應均不新增紀錄。看過仍以實際呈現為準，與已作答分開。
4. PK 在送出當下固定該次作答耗時，採用判定時以此計分，排除等待伺服器時間；保留既有公式與速度加分區間，不新增到時出局規則。挑戰模式保留等待判定時暫停倒數。重試計時依第九、十項規則。
5. 伺服器明確回傳正確選項識別，文字僅供顯示。共用流程驗證結果對應本次題目及其選項，再交由模式採用，不由模式從文案推導正解。

6. 第一次送出即鎖定選項，尚未取得有效判定時重試仍送同一選項。失敗不算答錯、不加分、不新增已作答紀錄；等待及重試連點只能有一個有效請求進行。
7. 三種模式均採 10 秒判題請求等待上限，與遊戲答題倒數及速度加分區間分開。連線失敗或逾時時顯示可重試狀態，由玩家明確重試，不背景無限重送；HTTP 錯誤及無效回應不得當成答錯。
8. 作答情境包含本次題目呈現及所屬回合／房間。換題、重新開始、離開模式或切換房間使舊請求失效；舊回應不得加分、寫已作答紀錄或解除新請求等待。題目循環後再次呈現同題也屬新情境。僅切換介面語言而保留當前題目時，仍可採用該題有效判定。

9. 挑戰與 PK 同次作答的重試沿用第一次有效送出時固定的作答時間，不因取得判定時的網路延遲或重試改變計分時間。公式不變，普通模式不新增時間計分。
10. 挑戰等待判定時暫停倒數；失敗後從該次請求送出前的剩餘時間繼續。等待玩家按重試的時間消耗倒數，後續失敗不得補回已耗時間。倒數先歸零則依既有規則結束並使後續回應失效；有效判定採用時計分仍用第九項固定時間。
11. 判定已採用後，已作答紀錄或分數儲存失敗不撤銷判定與本機遊戲結果，不重送判題、不再次加分。已作答紀錄以獨立操作重試，同一玩家與題目重複寫入不產生重複紀錄，本機仍知道該題已作答。排行榜與 PK 進度儲存失敗由模式呈現及處理，本輪不重做其同步／補送機制。

12. 共用流程區分可重試失敗與題目無法判定。題目已移除、選項無效或缺少正解等無法靠重送恢復的情況，顯示原因，不算答錯、不加分、不寫已作答紀錄，不反覆重送。模式收尾方式依第十五項。
13. 判定必須含本次題目 ID、送出選項 ID、正確選項 ID 及正誤，識別與正誤須互相一致。缺漏或矛盾視為無效回應，保留選項供重試。答案說明、嘲諷文字、原圖缺漏使用替代顯示，不阻止有效判定採用；圖片載入失敗不重送判題。
14. 已作答紀錄僅在目前頁面工作階段內保留補送，每筆初次失敗後最多自動補送兩次。仍失敗時保留本機已作答狀態並提示尚未同步；換題保留待補送項目，登出或切換帳號停止舊帳號補送。重新整理或關閉網頁後不保證恢復，本輪不新增持久化離線佇列。

15. 題目無法判定時：普通模式提示並由玩家明確換題，不增加或中斷連勝；挑戰停止倒數，標示本次中斷，保留已完成結果供查看，不算通關、不提交本次排行榜成績，提供返回入口，不自動重開每日挑戰或改變其參與限制；PK 停止本機作答，提示異常並提供離房入口，不自行跳題、不送虛構分數、不宣告勝方，沿用既有離房處理，不新增整房取消或裁定機制。
16. 測試集中於共用答題流程公開介面，涵蓋防重複、鎖定選項重試、10 秒逾時、結果識別與一致性、過期回應隔離、判定只採用一次、紀錄補送上限與帳號隔離。少量模式整合驗證普通連勝、挑戰倒數恢復與首次計分時間、PK 排除網路延遲及換題／離房隔離；三模式另驗證無法判定時的收尾及顯示／紀錄失敗不撤銷判定。

## 已查明現況

- 三種模式皆呼叫同一判題 API，分別處理結果與錯誤。
- 挑戰模式已具請求逾時、等待判定時暫停倒數及答案世代隔離；普通與 PK 尚未具相同保障。
- 普通與挑戰目前在有效判定前寫入作答紀錄；PK 未使用相同紀錄流程。
- PK 在判定回應後才設定已選選項，且以回應抵達時的經過時間計分。
- 正解選項標記目前由答案文字反推；本設計改採明確選項識別。
