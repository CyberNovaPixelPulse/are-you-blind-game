# 共用題池生命週期

狀態：測試邊界已確認，已發布為 [GitHub Issue #2](https://github.com/CyberNovaPixelPulse/are-you-blind-game/issues/2)，標記 ready-for-agent；尚未實作。

## Problem Statement

玩家在普通遊戲與挑戰模式中，需要穩定取得下一題。目前兩個模式分別管理待出題、補題與語言切換，容易出現行為不一致。尚未呈現的題目可能被記成看過；切換語言與補題同時發生時，舊結果可能干擾新題池；載入失敗也可能被當成題目耗盡，導致挑戰錯誤結束。

## Solution

讓兩種模式共用題池生命週期，提供一致的下一題體驗。只有實際呈現才算看過；普通隨機題目耗盡後可循環；切換語言從下一題生效；背景補題失敗時先繼續已有題目，沒有待出題時才顯示可重試錯誤。每日挑戰維持指定題目來源與順序，各模式保留自己的回合規則。

## User Stories

1. As a 普通模式玩家, I want 穩定取得下一題, so that 我能持續遊玩。
2. As a 挑戰模式玩家, I want 使用一致的題池行為, so that 模式切換不會帶來難以預期的載入差異。
3. As a 玩家, I want 只有實際呈現的題目才被記為看過, so that 預先載入不會消耗未看過的題目。
4. As a 玩家, I want 待出題彼此不重複, so that 不會在同一批準備題目中反覆看到同題。
5. As a 玩家, I want 補題盡可能排除當前題目, so that 下一題有變化。
6. As a 普通模式玩家, I want 優先看到未看過的題目, so that 我能探索更多內容。
7. As a 普通模式玩家, I want 未看過的題目耗盡後仍能循環遊玩, so that 題目數量有限時遊戲仍可繼續。
8. As a 只有一題可玩的玩家, I want 允許連續出現該題, so that 遊戲不會因去重而卡住。
9. As a 玩家, I want 切換語言時保留正在作答的題目, so that 當前作答不被中斷。
10. As a 玩家, I want 下一題起使用新語言的題池, so that 語言選擇能確實生效。
11. As a 玩家, I want 舊語言的待出題被丟棄, so that 不會繼續消耗過時的準備題目。
12. As a 玩家, I want 過期補題結果不影響新題池, so that 網路回應順序不會改變語言選擇結果。
13. As a 玩家, I want 優先取得指定語言的題目, so that 內容符合我的偏好。
14. As a 玩家, I want 指定語言不足時可補入其他語言並看到提示, so that 我能繼續遊玩且理解內容來源。
15. As a 玩家, I want 背景補題失敗時仍可遊玩待出題, so that 暫時網路問題不會立刻中斷遊戲。
16. As a 玩家, I want 後續能再次補題, so that 暫時失敗不會永久阻止遊玩。
17. As a 玩家, I want 沒有待出題且載入失敗時看到可重試錯誤, so that 我知道如何繼續。
18. As a 挑戰模式玩家, I want 載入失敗與真正耗盡被區分, so that 網路問題不會被算成通關。
19. As a 每日挑戰玩家, I want 保留指定題單與順序限制, so that 挑戰內容符合既定規則。
20. As a 每日挑戰玩家, I want 題單不混入隨機題且不循環, so that 每日挑戰的範圍明確。
21. As a 玩家, I want 倒數、計分、連勝、廣告及開始與結束規則保持既有行為, so that 題池重構不改變遊戲規則。
22. As a 維護者, I want 同時發生的補題要求安全合併, so that 不會重複加入題目或產生競態。
23. As a 維護者, I want 從共用題池的公開介面驗證行為, so that 模式可以共用可靠邏輯而不依賴內部實作。

## Implementation Decisions

- 建立有實質責任的共用題池模組，管理取得題目、待出題緩衝、補題、去重、同時補題要求合併與過期結果失效；普通遊戲及挑戰模式使用同一組生命週期規則。
- 模組的公開操作需能表達取得下一題、背景補題、切換語言或失效目前題池，以及確認題目已呈現；結果需區分可用題目、真正耗盡與載入失敗。具體命名由實作決定。
- 題目來源保留既有隨機抽題及每日指定題單兩種規則。保留現有品質加權、未作答優先及可玩性判定，不將共用模組簡化成請求包裝。
- 看過的題目指已實際呈現的題目；待出題指已準備但尚未呈現的題目。當前題目與待出題參與去重，但待出題不得被寫入持久化看過紀錄，包括重設看過紀錄的分支。
- 普通隨機題目優先未看過者，耗盡後允許新循環重用看過者，盡可能排除當前與待出題；只有一題可玩時允許連續重複。每日挑戰不套用此循環。
- 切換語言保留當前題目，丟棄原待出題，使舊請求失效；舊請求完成或清理時不得修改新題池或新請求狀態。
- 保留指定語言優先、題目不足時補入其他語言的既有政策及提示，提示應符合有效題池的實際來源；每日挑戰不加入隨機補題。
- 背景失敗保留可用待出題並允許後續重試。只有要求下一題且沒有待出題時，才顯示可重試載入錯誤；真正耗盡交由模式決定結束行為。
- 各模式負責倒數、計分、連勝、廣告、回合開始與結束；圖片預載可依模式需求安排。整合時保留這些行為，明確同意的失敗處理修正除外。
- 不要求資料庫結構或對外 API 合約變更；若實作發現必要變更，應先記錄原因與相容性影響。

## Testing Decisions

- 以共用題池的公開介面作為唯一主要自動化測試邊界，透過可控制回應時機的題目來源與看過紀錄儲存替身，驗證外部可觀察結果；不測內部陣列、私有狀態或函式呼叫次數。
- 覆蓋同時補題不重複、只有呈現才持久化看過紀錄、循環後可繼續、單題不死鎖、語言切換及舊回應晚到、舊清理不干擾新請求、語言補題提示、背景失敗仍可前進、空題池失敗可重試，以及真正耗盡與失敗的區別。
- 在相同邊界測試每日指定來源與順序限制、不隨機補題與不循環；保留既有抽題政策的可觀察結果。
- 普通模式、挑戰模式及每日挑戰另外進行少量整合驗收，確認實際呈現才記錄看過、語言切換從下一題生效、錯誤不造成通關，以及倒數、計分、連勝、廣告與回合流程沒有回歸。
- 目前專案沒有既有自動化測試檔、測試指令或測試框架可沿用。實作時採用足以執行上述行為測試的最小測試設定，避免為每個輔助函式新增測試邊界。

## Out of Scope

- 題目發布流程與圖片清理修正。
- 答案提交流程重構。
- 品質加權或抽題推薦演算法調整。
- 計分、倒數、連勝、廣告、付費及模式規則重新設計。
- 其他遊戲模式的擴充、部署與正式環境發布。
