# Issues #10 / #11 — 明確重審與發布到期

來源：GitHub #10、#11，父規格 #7。沿用共用發布流程、伺服器取消裁決與安全清理工作者。

## 行為

- 審核證明過期先確認是否已發布。查詢與普通重試不啟動新審核；需要時由使用者明確選擇重新審核並繼續，固定內容與識別不變。
- 審核證明與其登記回應分開保留：登記回應遺失時重試同一證明，不因此再買一次審核。有效登記與繼續提交均在伺服器驗證證明後更新期限。
- 完整合格圖片可沿用；缺失或雜湊不符時指出需補傳的角色。只有符合固定內容的位元組能修復該路徑，提交仍重新驗證兩張圖片，並將已驗證的證明期限帶入資料庫，在取得發布鎖後、成立題目前檢查；圖片讀取或鎖等待期間過期不能成立題目。
- 修改內容前先取得原發布裁決並關閉尚未成立的舊識別，避免已發出但晚到的提交造成重複發布。重用目前已有的取消裁決操作，不等待圖片清理；編輯／新發布與清理的完成時間獨立。結果不明不解鎖編輯；其實已發布時顯示原結果。
- 介面語言切換不更動固定的題目語言；修改及過期後重新開始必須明確操作，取得新識別、重審並重新上傳。

## 到期與持久化

- 未完成發布自最後有效操作保留二十四小時。成功上傳、通過證明驗證的重審登記及繼續提交更新期限；單純查詢、重複 begin、失敗的圖片上傳或無效證明不更新。
- 查詢與修改操作都在同一發布資料列鎖下檢查期限。到期標為 expired，清除 snapshot 與不再需要的圖片雜湊，留下識別、擁有者、終態及清理所需的最小清單；舊識別不得復活。
- 排程工作者先以 skip-locked 處理到期，再沿用引用防護、清理租約、有限重試與公平領取順序。正在提交且持鎖的項目會暫緩；已成立題目不會被到期清理。
- 關閉頁面不送取消，也不承諾恢復完整表單。仍保有檔案與內容的頁面可在看到已過期後明確建立新發布。
